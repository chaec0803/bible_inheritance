# TDD와 회귀 테스트 작업 규칙

1. 새 기능 또는 버그의 기대 동작을 `docs/FEATURES.md`에 먼저 적는다.
2. 기대 동작을 재현하는 실패 테스트를 먼저 추가하고 실패를 확인한다.
3. 테스트를 통과하는 최소 구현을 한다.
4. `pnpm test`, `pnpm lint`, `pnpm exec tsc --noEmit`, `pnpm build`를 모두 통과시킨다.
5. 사용자 핵심 흐름이 바뀌면 배포 전 브라우저 스모크 테스트도 갱신한다.
6. 기능 삭제는 관련 테스트와 인벤토리 항목을 함께 삭제하거나 새 정책으로 수정한다.

테스트 이름은 구현 방식이 아니라 사용자가 기대하는 동작을 한국어나 명확한 영어 문장으로 표현한다.
